# pdf-editing-lib

Zero-dependency PDF generation engine written in TypeScript.

## Features

- Pure `Uint8Array` PDF writer
- PDF 1.4 output with classic xref tables
- Text rendering with standard 14 fonts
- Wrapped and aligned text blocks
- Embedded TrueType fonts with Unicode text, common GSUB ligatures, and kerning-aware `TJ` serialization
- Font fallback across built-in and embedded fonts for mixed-script text
- Basic LTR/RTL direction control with automatic right alignment for RTL text blocks, contextual Arabic joining forms, and ZWJ/ZWNJ shaping control support
- Embedded JPEG and PNG image support, including PNG transparency masks and alpha-channel soft masks
- PDF parsing and inspection helpers for classic xref tables plus xref/object streams, including Standard Security Handler revision 2 decryption
- Incremental editing for classic and xref-stream PDFs, including encrypted PDFs, with metadata updates, page append/insert/reorder/remove, existing-page overlay content, form flattening, and field value updates
- AcroForm text fields, choice fields, check boxes, radio groups, push buttons, and signature fields with parser inspection helpers
- URI link annotations plus highlight, note, and free-text annotations
- Internal page link annotations
- Named destinations and outline bookmarks
- Page labels and embedded file attachments
- XMP metadata streams
- Tagged PDF foundations with coordinate-free flow authoring, document language, marked content, grouped logical structure output for wrapped/fallback text, document roots, role maps, arbitrary nested containers, table/list/link structure trees, inferred structure bounding boxes, per-node language/actual text, image alt text, and parser inspection that maps structure MCIDs/OBJR annotations back to content
- PDF/A-1b-style output mode with autogenerated conformance XMP, sRGB output intents, and compliance warnings
- Optional veraPDF validation runner for standards-level PDF/A/PDF/UA checks
- Password protection and permissions for generated PDFs, with legacy `rc4-40` compatibility and stronger `rc4-128` defaults
- Page transfer utilities for extract, split, merge, and append/import workflows
- Vector paths, colors, transforms, and graphics state control
- Deterministic serialization for stable tests
- Node and browser-friendly output helpers

## Quick Start

```ts
import { createDocument, rgb } from "pdf-editing-lib";

const doc = createDocument({
  info: {
    title: "Hello PDF",
    author: "Codex",
    creationDate: "D:20260413210000Z"
  },
  xmpMetadata: {
    title: "Hello PDF",
    creator: "Codex",
    createDate: "2026-04-13T21:00:00Z",
    modifyDate: "2026-04-13T21:00:00Z",
    metadataDate: "2026-04-13T21:00:00Z"
  }
});

const page = doc.addPage({ size: "A4" });
page.text("Hello from TypeScript", {
  x: 56,
  y: 780,
  fontSize: 18,
  color: rgb(0.13, 0.2, 0.34)
});
page.textBlock("Wrapped copy with centered alignment and predictable line breaks.", {
  x: 56,
  y: 740,
  width: 220,
  fontSize: 12,
  lineHeight: 16,
  align: "center"
});

doc.addNamedDestination("intro", page);
doc.addOutline("Introduction", "intro");
doc.setPageLabel(page, { style: "decimal", prefix: "Intro-" });
doc.attachFile("notes.txt", new TextEncoder().encode("hello"), {
  description: "Build notes",
  mimeType: "text/plain"
});

const bytes = doc.toUint8Array();
```

For streaming-style output targets, write to a byte sink:

```ts
import { BufferSink, NodeStreamSink, createDocument } from "pdf-editing-lib";
import { createWriteStream } from "node:fs";

const doc = createDocument();
doc.addPage().text("Hello PDF", { x: 56, y: 760 });

await doc.writeTo(new NodeStreamSink(createWriteStream("hello.pdf")));

const memorySink = new BufferSink();
await doc.writeTo(memorySink);
const memoryBytes = memorySink.collect();
```

## veraPDF validation

`validateCompliance()` is intentionally a lightweight preflight. For standards-level validation, install veraPDF and run:

```sh
npm run validate:pdf -- output.pdf
```

You can point to a custom executable and pass veraPDF-specific options after `--`:

```sh
VERAPDF_BIN=/opt/verapdf/verapdf npm run validate:pdf -- output.pdf
npm run validate:pdf -- output.pdf -- --flavour 1b
npm run validate:pdf -- --format xml output.pdf
```

```ts
const accessible = createDocument({
  conformance: "pdfua-1",
  tagged: true,
  language: "en-US",
  structureRoot: "Document",
  info: {
    title: "Quarterly Report"
  },
  xmpMetadata: {
    title: "Quarterly Report",
    creator: "Accessibility Team",
    createDate: "2026-05-05T00:00:00Z",
    modifyDate: "2026-05-05T00:00:00Z",
    metadataDate: "2026-05-05T00:00:00Z"
  }
});

const font = accessible.embedTrueTypeFont(fontBytes, { family: "AccessibleSans" });
const accessiblePage = accessible.addPage();
accessiblePage.flow({ font })
  .heading("Quarterly Report")
  .paragraph("Revenue, support volume, and accessibility work completed during Q1.")
  .png(logoBytes, {
    width: 32,
    altText: "Company logo"
  });

const accessibilityIssues = accessible.validateCompliance();
```

The `flow()` helper is the recommended path for tagged authoring: it keeps a cursor, assigns standard tags for headings and paragraphs, lays out tables and images, applies standard report spacing, and infers structure bounding boxes. Low-level methods such as `text()`, `png()`, and `link()` still accept explicit coordinates when you need exact placement.

Spacing is semantic by default instead of one fixed gap after every element:

- paragraphs: compact rhythm after the text
- headings: stronger space before, smaller space after, with no leading space at the top of a page
- tables and figures: object spacing before and after
- links: paragraph-like spacing after the link

Use `spaceBefore` and `spaceAfter` on any flow/template block for one-off adjustments, or set `page.spacing` in `renderTemplate()` for a document-wide scale.

For production report templates, render a reusable block tree and let the document create pages as content flows:

```ts
doc.renderTemplate({
  info: {
    title: "Accessibility Audit Report",
    author: "BarrierBreak"
  },
  xmpMetadata: {
    title: "Accessibility Audit Report",
    creator: "BarrierBreak",
    createDate: "2026-05-05T00:00:00Z",
    modifyDate: "2026-05-05T00:00:00Z",
    metadataDate: "2026-05-05T00:00:00Z"
  },
  page: {
    size: "A4",
    font,
    spacing: {
      paragraphAfter: 8,
      headingBefore: { 2: 18, 3: 14 },
      headingAfter: { 1: 14, 2: 10, 3: 8 },
      tableBefore: 6,
      tableAfter: 14
    }
  },
  blocks: [
    { type: "heading", text: "Accessibility Audit Report" },
    { type: "paragraph", text: "Executive summary and scope." },
    {
      type: "table",
      rows: [
        [{ text: "Criterion", header: true }, { text: "Result", header: true }],
        ["Language metadata", "Present"]
      ],
      options: { headerRows: 1 }
    },
    { type: "pageBreak" },
    { type: "heading", text: "References", options: { level: 2 } },
    { type: "link", text: "WCAG 2.2", url: "https://www.w3.org/TR/WCAG22/" }
  ],
  header: ({ title, pageNumber, totalPages }) => [
    {
      type: "paragraph",
      text: `${title ?? "Report"} - page ${pageNumber} of ${totalPages}`,
      options: { fontSize: 8, tag: "Artifact" }
    }
  ],
  pageNumber: {
    region: "footer",
    align: "center"
  }
});
```

Use `{ type: "pageBreak" }` when a report section must start on the next page. If a page break appears before any body content on a page, it is ignored instead of creating a blank page.

Headers and footers are rendered after pagination, so callbacks receive `title`, `author`, `pageNumber`, and `totalPages`. Use `pageNumber` for a standard running page label without writing your own footer; `region` can be `"header"` or `"footer"`, and `align` can be `"left"`, `"center"`, or `"right"`.

Tagged and PDF/A-conformance documents now support a safe incremental-edit subset: metadata/XMP updates, overlay edits on existing pages, and appending new compliant pages. Reordering pages, removing pages, mid-document inserts, and form flattening are still blocked until full structure-tree-safe editing lands.

```ts
import { createDocument } from "pdf-editing-lib";

const doc = createDocument();
const page = doc.addPage({ size: "Letter" });
page.textField("email", {
  x: 48,
  y: 620,
  width: 220,
  height: 24,
  value: "ada@example.com",
  required: true
});

const bytes = doc.toUint8Array();
```

## Development

```bash
npm install
npm test
npm run docs
npm run example:hello
npm run example:image
npm run example:png
npm run example:web
```

`npm run docs` generates TypeDoc API Markdown and builds the VitePress site in `docs/.vitepress/dist`.
Use `npm run docs:dev` to work on the docs locally, then open the printed localhost URL.
