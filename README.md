# pdf-editing-lib

Zero-dependency PDF generation engine written in TypeScript.

## Features

- Pure `Uint8Array` PDF writer
- PDF 1.4 output with classic xref tables
- Text rendering with standard 14 fonts
- Wrapped and aligned text blocks
- Embedded TrueType fonts with Unicode text, common GSUB ligatures, and kerning-aware `TJ` serialization
- Font fallback across built-in and embedded fonts for mixed-script text
- Basic LTR/RTL direction control with automatic right alignment for RTL text blocks, contextual Arabic joining forms, and ZWJ/ZWNJ shaping control support
- Embedded JPEG and PNG image support, including PNG transparency masks and alpha-channel soft masks
- PDF parsing and inspection helpers for classic xref tables plus xref/object streams, including Standard Security Handler revision 2 decryption
- Incremental editing for classic and xref-stream PDFs, including encrypted PDFs, with metadata updates, page append/insert/reorder/remove, existing-page overlay content, form flattening, and field value updates
- AcroForm text fields, choice fields, check boxes, radio groups, push buttons, and signature fields with parser inspection helpers
- URI link annotations plus highlight, note, and free-text annotations
- Internal page link annotations
- Named destinations and outline bookmarks
- Page labels and embedded file attachments
- XMP metadata streams
- Tagged PDF foundations with document language, marked content, grouped logical structure output for wrapped/fallback text, document roots, role maps, arbitrary nested containers, table/list/link structure trees, per-node language/actual text, image alt text, and parser inspection that maps structure MCIDs/OBJR annotations back to content
- PDF/A-1b-style output mode with autogenerated conformance XMP, sRGB output intents, and compliance warnings
- Optional veraPDF validation runner for standards-level PDF/A/PDF/UA checks
- Password protection and permissions for generated PDFs, with legacy `rc4-40` compatibility and stronger `rc4-128` defaults
- Page transfer utilities for extract, split, merge, and append/import workflows
- Vector paths, colors, transforms, and graphics state control
- Deterministic serialization for stable tests
- Node and browser-friendly output helpers

## Quick Start

```ts
import { createDocument, rgb } from "pdf-editing-lib";

const doc = createDocument({
  info: {
    title: "Hello PDF",
    author: "Codex",
    creationDate: "D:20260413210000Z"
  },
  xmpMetadata: '<x:xmpmeta xmlns:x="adobe:ns:meta/"><rdf:RDF xmlns:rdf="http://www.w3.org/1999/02/22-rdf-syntax-ns#"><rdf:Description xmlns:dc="http://purl.org/dc/elements/1.1/"><dc:title>Hello PDF</dc:title></rdf:Description></rdf:RDF></x:xmpmeta>'
});

const page = doc.addPage({ size: "A4" });
page.text("Hello from TypeScript", {
  x: 56,
  y: 780,
  fontSize: 18,
  color: rgb(0.13, 0.2, 0.34)
});
page.textBlock("Wrapped copy with centered alignment and predictable line breaks.", {
  x: 56,
  y: 740,
  width: 220,
  fontSize: 12,
  lineHeight: 16,
  align: "center"
});

doc.addNamedDestination("intro", page);
doc.addOutline("Introduction", "intro");
doc.setPageLabel(page, { style: "decimal", prefix: "Intro-" });
doc.attachFile("notes.txt", new TextEncoder().encode("hello"), {
  description: "Build notes",
  mimeType: "text/plain"
});

const bytes = doc.toUint8Array();
```

## veraPDF validation

`validateCompliance()` is intentionally a lightweight preflight. For standards-level validation, install veraPDF and run:

```sh
npm run validate:pdf -- output.pdf
```

You can point to a custom executable and pass veraPDF-specific options after `--`:

```sh
VERAPDF_BIN=/opt/verapdf/verapdf npm run validate:pdf -- output.pdf
npm run validate:pdf -- output.pdf -- --flavour 1b
npm run validate:pdf -- --format xml output.pdf
```

```ts
import { editDocument } from "pdf-editing-lib";

const editable = editDocument(existingPdfBytes, { password: "reader" });
editable.updateInfo({
  title: "Revised Draft",
  modificationDate: "D:20260414091500Z"
});
editable.setXmpMetadata('<x:xmpmeta xmlns:x="adobe:ns:meta/"><rdf:RDF xmlns:rdf="http://www.w3.org/1999/02/22-rdf-syntax-ns#"><rdf:Description xmlns:dc="http://purl.org/dc/elements/1.1/"><dc:title>Revised Draft</dc:title></rdf:Description></rdf:RDF></x:xmpmeta>');

editable.movePage(2, 0);
editable.removePage(1);

const page = editable.insertPage(1);
page.text("Incrementally appended page", { x: 48, y: 780 });

const updatedBytes = editable.toUint8Array();
```

Tagged and PDF/A-conformance documents now support a safe incremental-edit subset: metadata/XMP updates, overlay edits on existing pages, and appending new compliant pages. Reordering pages, removing pages, mid-document inserts, and form flattening are still blocked until full structure-tree-safe editing lands.

```ts

const doc = createDocument();

page.textField("email", {
  x: 48,
  y: 620,

  height: 24,

  required: true
```

## Development

```bash
npm install
npm test
npm run docs
npm run example:hello
npm run example:image
npm run example:png
npm run example:web
```

`npm run docs` generates TypeDoc API Markdown and builds the VitePress site in `docs/.vitepress/dist`.
Use `npm run docs:dev` to work on the docs locally, then open the printed localhost URL.

## Website Example

This repo also includes a browser demo in [examples/website/index.html](/Users/criston/Documents/learning/pdf-editing-lib/examples/website/index.html) that imports the built library from `dist/`, previews PDFs in an iframe, creates a new PDF from form input, and incrementally edits uploaded PDFs.

Run it locally with:

```sh
npm run example:web
```

Then open [http://localhost:4173/](http://localhost:4173/).
